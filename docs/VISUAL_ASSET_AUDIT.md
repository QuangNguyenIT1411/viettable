# VietTable visual asset audit

Audited on 2026-09-24 against the local Gateway at `http://127.0.0.1:5100`, the Samsung SM-A528B debug app, and the production-built customer web. Branch artwork below is **demo/illustrative imagery generated by AI**, not photography of a real VietTable location.

## Branch images

Catalog owns branch metadata and persists `Branches.Image`. Gateway serves the public `/images/...` paths and exposes the same `image` field in branch list and detail. The startup repair adds the nullable column if needed and fills only empty image fields on the three named demo branches. It does not replace a nonempty/admin-supplied path. No Docker volume or branch row was reset.

## Verification

Run `powershell -ExecutionPolicy Bypass -File .\scripts\test-production-images.ps1` from `SelfRestaurant-master` with Gateway running. The script checks list/detail consistency, 3 unique branch bytes, all branch-menu image URLs, 3 heroes, HTTP status, MIME, nonzero content, Pillow decode, and minimum dimensions. It needs Python with Pillow on the test host.

Result on 2026-09-24: branches **3/3**, menu images **52 unique URLs / 52 active items per branch**, heroes **3/3**, broken required image URLs **0**. Branch covers are 1672×941; all images decoded. Catalog and Gateway Docker builds passed, and the rebuilt containers served the new paths. Android `:app:assembleDebug :app:testDebugUnitTest` passed. APK installed on Samsung SM-A528B; `adb reverse tcp:5100 tcp:5100` remained active. Home, branch list, all three details, menu after branch switch, and scroll/back were visually checked without wrong-branch imagery. Customer web branch cards and hero backgrounds were checked in browser at desktop/mobile widths. No full payment or ONSITE regression was run because this change is asset/binding scoped.
