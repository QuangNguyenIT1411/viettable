# VietTable UX Fix Audit — final acceptance 05/10/2026

Scope: controlled post-demo fixes for timestamp display, QR/manual entry, DiningSession order history, invoice history, and reservation history. No database/volume reset, production deployment, or push was performed.

Android previously parsed that form as local wall time. Some web pages also passed offsetless API values directly to `new Date(...)`, which browsers interpret as local time. | Android `DisplayFormatters` treats offsetless API ISO values as UTC, preserves explicit offsets, and formats the resulting instant in the device timezone. Reservation parsing now uses the same parser instead of appending `Z` to already-offset values. Customer/Chef/Cashier web API date displays use small local date helpers that append UTC only when the API value has no zone. Business dates remain local. No fixed `+7` arithmetic was added. | Unit tests cover offsetless UTC, `Z`, explicit `+07:00`, date boundary, and malformed input. ## API ownership and security

- Customers owns reservations (`RESTAURANT_CUSTOMERS`); Gateway derives the customer actor from the JWT and calls the existing Customers API.
- Orders owns order/session history. Session summaries are loaded only from Orders-owned data.
- Billing owns invoice/payment reads. The Gateway passes the customer ID from the JWT; Billing applies `Invoice.CustomerId` filtering. Existing detail lookup remains owner-checked.
- No client-supplied customer ID is used to widen a history query.
