# PostgreSQL compatibility — phase 1

Ngày 05/10/2026. Branch `cloud/postgres-migration`, base `40a0f59`. No cloud deployment or SQL Server cutover.

## Provider and ownership

.NET/EF stay 8 / 8.0.11; Npgsql.EntityFrameworkCore.PostgreSQL 8.0.11 added to five APIs. Gateway has no DbContext. Default when `Database__Provider` is absent is **SqlServer**, preserving local Compose. `Postgres` requires named owning connection; it never falls back to `RestaurantDb`.

| API | PostgreSQL schema / history | Environment connection name |
|---|---|---|
| Catalog | catalog / catalog.__EFMigrationsHistory | ConnectionStrings__CatalogDb |
| Orders | orders / orders.__EFMigrationsHistory | ConnectionStrings__OrdersDb |
| Customers | customers / customers.__EFMigrationsHistory | ConnectionStrings__CustomersDb |
| Identity | identity / identity.__EFMigrationsHistory | ConnectionStrings__IdentityDb |
| Billing | billing / billing.__EFMigrationsHistory | ConnectionStrings__BillingDb |

Runtime URLs retain actual existing keys `Services__Catalog`, `Services__Orders`, `Services__Customers`, `Services__Identity`, `Services__Billing`. Do not invent `...BaseUrl` keys. Local localhost defaults remain; cloud must supply private service URLs. Only Gateway public; several internal APIs trust Gateway commands and must not be internet exposed.

Set `MobileJwt__SigningKey` from a secret manager consistently (Gateway, Identity, Billing); at least 32 UTF-8 bytes. Never rotate per restart. `PORT` binds all six APIs to `http://0.0.0.0:<PORT>`; without PORT existing ASPNETCORE_URLS behavior remains. TLS terminates at trusted HTTPS reverse proxy, not dev certificates.

## Migrations / bootstrap

PostgreSQL baselines live under each owner's `Persistence/Postgres/Migrations` with its own snapshot. SQL Server historical artifacts/bootstrap remain untouched. Design factories scaffold PostgreSQL without opening a database; their credential-free design connection is **not** runtime configuration.

Runtime defaults: `Database__ApplyMigrations=false`, `Database__SeedProfile=None`. Startup validates migrations and fails closed if any are pending. On **one controlled migration/bootstrap job per owner**, set owning connection, `Database__Provider=Postgres`, `Database__ApplyMigrations=true`, `Database__SeedProfile=Reference`, and run the published owner API until readiness. Stop job; restart normal persistent service with ApplyMigrations=false / SeedProfile=None. Do not run seed jobs concurrently or across replicas. A separate exit-after-migration CLI is not implemented in phase 1.

Reference seeds: Catalog four table statuses, Orders seven existing order statuses, Identity six employee role codes. Customers/Billing need no fabricated reference records. `Demo` is explicit isolated-empty-data only: minimal branch/table/menu/dish/recipe graph; no customer/employee/password/reservation/session/payment is seeded. Production needs approved data import or legitimate management API provisioning, not Demo. IDs are generated, not assumed equal to SQL Server IDs.

Identity adds its local CustomerLoyalty view and separate `PostgresAccountCaseSemantics` migration for Username/Email `citext`. Database-level extension installation may require a privileged migration principal on Supabase; verify extension schema/search_path before cutover. Runtime users must not have cross-schema grants. The disposable test superuser does not prove least privilege.

Future EF scaffolding: review keyless `CustomerLoyalty` view metadata. EF 8 generated `ToTable(null, "identity")` throws; current designer/snapshot correctly use `ToTable((string)null)` plus `ToView`. Review generated diffs before running migrations. Never point PostgreSQL design factory update commands at SQL Server. Do not use EnsureCreated in place of migration history.

## Mapping / semantics

- Explicit original quoted table/column names in five schemas; no cross-schema navigation/FK.
- Instant DateTime fields → timestamptz, UTC reads; Local converted to UTC; Unspecified rejected rather than guessing timezone. DateOnly business dates remain `date`. No +7 offset in backend.
- Money retains decimal precision → numeric; no float conversion. Partial indexes translated only for reviewed known filters. Unknown defaults/filters fail model creation.
- IngredientBatches SQL Server rowversion remains native. PG uses application-generated bytea concurrency token on writes; not a fake SQL rowversion type.
- App-side Guid.NewGuid / existing public codes preserved.
- Inventory raw UPDATE → atomic ExecuteUpdate predicate; no request-time T-SQL DDL on PG.
- Locks: transaction-scoped SHA256-derived pg_advisory_xact_lock, ten-second lock timeout; SQL sp_getapplock kept. Payment locks remain around persisted quote/payment/part/invoice commit. Reconciliation remains persistent background work.
- SERIALIZABLE reservation/check-in/order protections retained. PG serialization/deadlock conflicts → HTTP 409 `command_in_progress`, not automatic whole-handler retries (downstream side effects). Retry with original idempotency key **after REST resync**. Cold Catalog snapshot PK contention is not converted to “dish unavailable”. Other DB errors are not blanket-mapped to conflicts.

## Storage / broker / readiness

`IDishMediaStorage` isolates dish uploads; Local implementation preserves current public paths. `MediaStorage__Provider=Local` remains default. Unsupported provider fails startup; object storage adapter/credentials/path migration are next phase. Railway writable disk is not a production media solution.

Orders/Billing event JSONL is optional diagnostic copy: production structured stdout metadata; `IntegrationEvents__WriteDiagnosticFiles=false`. DB outbox/inbox and BusinessAuditLogs are retained. Diagnostic IO failure no longer suppresses Rabbit publishing. Existing publisher persistence behavior/event delivery workers are not redesigned.

`RabbitMq__Uri` accepts amqp/amqps via RabbitMQ.Client 6.8.1 factory, retaining TLS certificate validation. Existing Host/Port/UserName/Password config remains compatible. URI values never logged. Configuration tests do not claim live managed broker/TLS E2E.

Four existing workers remain persistent hosted services: Catalog table release, Customers ready consumer, Orders payment-completed consumer, Billing reconciliation. They are not moved to serverless functions. Gateway readyz checks five downstream readyz endpoints (parallel, bounded timeout); five APIs check DB connectivity; healthz is liveness. No health check writes business data.

## Rollback

Phase 1 has no cutover: existing SQL Docker images/volumes and .env are preserved. Select SqlServer with original owning connections/URLs; do not apply PostgreSQL migrations there. Deployment rollback should restore approved previous artifact/config, not git reset. Future cloud rollback requires frozen writes + validated backup/restore and event/payment reconciliation, not simply changing provider after users write PostgreSQL.
